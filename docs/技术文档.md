# 小说下载器(bookdl)技术文档

> 版本:v1.8.1 · 日期:2026-09-13(初版 2026-09-05) · 仓库:[WakuOOXX/novel-downloader](https://github.com/WakuOOXX/novel-downloader)
> 功能:读取开源阅读(Legado)书源包 `bookSource.json`,输入书名搜索,命中后抓取整本正文,导出 **TXT** 与 **EPUB3**。

## 1. 概述

程序是**纯 Python + tkinter 桌面应用**,不依赖浏览器内核。核心难点在"读懂 Legado 书源规则":书源不是固定的 API,而是一段段**选择器 DSL**(类 CSS / XPath / JSONPath + 正则替换),本程序在 `legado/rules.py` 中实现该 DSL 的**纯规则子集**,再由 `engine.py` 编排"搜索 → 目录 → 正文"并多线程加速。

### 输入输出
- 输入:书名关键词 + 可选书源分组过滤;输出:整本书的 `.txt`(UTF-8 BOM)与 `.epub`(EPUB3)。
- 多源聚合:同一关键词并发打向数百个书源,结果按"书源+书籍URL"去重后展示。

### 已实测(2026-09-05)
用一个公开 Legado 书源做了端到端验证:搜索命中 18 条 → 目录 1625 章 → 正文逐章抓取 → TXT/EPUB 导出,EPUB 结构校验通过。(样章曾归档于 `samples\`,已随发布清理。)

> 📌 **单一数据源约定**:本节数字为权威记录。实测数据更新时以本节为准,并同步 README。

## 4. 书源包数据结构(bookSource.json)

顶层为 JSON 数组。解析统计(2026-09-05):

- **3393 个书源**,`enabled` 全部为 `true`;分组取值 **252 种**(引擎 `source_groups` 口径:按 `bookSourceGroup` **整串**计数,含 1 个 `(未分组)` 占位;未分组源 590 个)。
- 字段 29 种;10 个核心字段 100% 覆盖:`bookSourceName/Type/Url/customOrder/enabled/enabledCookieJar/enabledExplore/lastUpdateTime/respondTime/weight`。
- 规则字段覆盖率:`ruleBookInfo` 3026、`ruleToc` 3022、`ruleContent` 3021、`ruleSearch` 3018、`ruleExplore` 3007;`searchUrl` 2877;`loginUrl` 2076;`header` 1604。
- `bookSourceType` 分布(常见约定,未经官方枚举声明):`0`(文本书源)3176、`2`(漫画/图源类)119、`1` 62、`3`(网盘/特殊发现类,如坚果云盘)33、`4` 3。

### 关键字段语义(引擎实际使用的)

| 字段 | 类型 | 用途 |
|---|---|---|
| `bookSourceName` | str | 展示名(亦作 HTTP 会话隔离 key) |
| `bookSourceUrl` | str | 站点根;用于解析相对 searchUrl |
| `searchUrl` | str | 搜索请求:`URL` 或 `URL,\n{json}`(json 可含 method/body/headers) |
| `ruleSearch` | obj | 搜索结果解析:`bookList`(集合规则)+ `name/author/bookUrl/kind/intro/lastChapter`(单值规则) |
| `ruleToc` | obj | 目录解析:`tocUrl`、`chapterList`(集合)、`chapterName/chapterUrl`(单值)、`nextTocUrl`(目录分页) |
| `ruleContent` | str/obj | 正文:`content` 规则,可选 `nextContentUrl`(正文分页)、`replaceRegex`(多条,`##正则##替换##` 链或按行多条) |
| `ruleBookInfo` | obj | 书籍信息(引擎仅用其 `tocUrl` 作为目录入口) |
| `header` | str | 请求头 JSON(`@js` 生成则忽略,回退默认 UA) |
| `respondTime` | int | 源超时(ms),引擎换算秒后夹取在 **[4, 12]s** |
| `enabled` | bool | 是否参与搜索 |

## 5. 架构与数据流

```
GUI(app.py) ──线程──> engine.search_sources(并发N源)  ──> 候选列表(去重)
                          │
GUI 选中一条 ──线程──> engine.load_book
                          ├─ fetch_toc(含目录分页,≤8页)
                          └─ 章节池并发(10线程)逐章 _fetch_chapter
                               ├─ 正文抽取 + HTML→文本 + replaceRegex
                               └─ 正文分页拼接(≤20页/章)
                          │
export.export_txt / export_epub ──> downloads\
```

### 5.1 GUI 线程模型(app.py)
- 全部耗时操作跑**后台线程**,UI 线程只通过 `queue.Queue` + `root.after(120, drain)` 事件泵消费消息(`log/sprog/hit/sres/dlprog/dlok/dlerr`),避免 tkinter 线程竞争。
- `threading.Event`(`stop_search`/`stop_dl`)实现搜索/下载取消。
- 搜索并发 384、正文下载并发 10(常量 `SEARCH_WORKERS`/`DOWNLOAD_WORKERS`,见 §5.5);单源超时由 §4 `respondTime` 换算后夹取 **[4,12]s**,抑制死源拖尾。

### 5.2 搜索(search_sources,engine.py)
1. 预筛:必须 `enabled` 且有 `searchUrl`、`ruleSearch` 为 dict 且含 `bookList`,且 `critical_js()` 为空(见 §6.4;**v1.7.0 起 JS 引擎可用时不再因 JS 跳过**)。整批源只预筛一次。
2. 每个源独立任务:`parse_request` 展开 `{{key}}/{{page}}`;searchUrl 为相对路径时用 `bookSourceUrl` 解析;请求头 = `header` 字段 ∪ 请求配置内 headers。
3. 取回后 `UnicodeDammit` 解码 → `BeautifulSoup(lxml)` → `extract_list(bookList)` 得候选节点;对每个节点用单值规则取 `name`(必填)、`author`、`bookUrl`(必填,相对→绝对)、`kind` 等;取出的字段**全部过清洗器**(见 §5.2.2,规则实现已收敛至 `legado/normalize.py`)。
4. 结果去重(同源同 URL,键 = `(书源名, book_url)`)后做**跨源同书合并**(见 §5.2.3):返回列表中同书行相邻,并注记 `_group_key/_src_count/_group_first`。
5. **增量上屏(2026-09-09 取舍定案)**:`on_hit(hit)` 对每一条命中**即时**回调(逐条插行,实时性优先)。即时条目**不带**跨源同书分组注记(合并需等整轮结果),GUI 过程态用 fallback 键自成一组(短暂视觉乱,无害);`sres` 搜索结束事件里 GUI **必做** `merge_hits(dedupe_hits(...)) + _ordered_hits + _fill_results` 整表重建,分组/相邻/排序以最终态为准。`on_progress(done,total,"源名 ×命中数")` 刷新进度;任一源失败仅记空,不中断整体。

#### 5.2.1 模糊搜索(2026-09-05 新增)
- 开关参数 `fuzzy`(GUI 复选框"模糊搜索",默认开)。
- **变体重试**:直搜 **0 命中**时,`make_key_variants(key)` 生成变体——(a) 按空格/标点/书名号取**首段**(兼容"书名 作者"粘贴);(b) **去尾字**(≥4 字时,`斗破苍X → 斗破苍`);(c) 超长时**截前 4 字**。只对**上一轮网络存活源**(HTTP 成功且页面非空)逐变体重试,命中即停、变体耗尽即止——避免对上千死源放大请求。
- **客户端排序**(app.py `_score_hit`,2026-09-08 增强):模糊开启时完成态重排,按**多字段加权**打分:书名精确同名 100 > 书名含关键词 80 > 变体命中书名 60 > 作者含关键词 +40 > 分类含关键词 +25 > 简介含关键词 +15;全不命中时退 `difflib` 字符相似度 ×30。精确模式保持到达顺序。

#### 5.2.2 结果字段清洗 + "只看相关结果"(2026-09-08 新增)

**背景**:很多小站无视搜索词、直接返回热门书充数,且部分源的字段规则抽错列(书名里混"作者: xxx连载"、作者栏是整行"书名+分类+章节"、分类栏带站点计数等)。

**四字段清洗器**(v1.3 起位于 `legado/normalize.py`,engine.py 搜索与详情页补全共用;书名先清洗再联动判定其余字段):

| 函数 | 字段 | 规则 |
|---|---|---|
| `clean_name` | 书名 | 去 `&nbsp;` 类实体;混入"作者:/最新章节"等后续字段时截断;去"XX 著"尾(参照 LegadoParser `Fmt.bookNameRegex`);迭代去"TXT下载/TXT全本/全文阅读/无弹窗/免费下载/(完结)/TXT/下载/连载"类网站尾巴(书名 ≤4 字时不动,防误伤);规整空白 |
| `clean_author` | 作者 | 去"作者[:：>》]"前缀与"著"尾缀;作者==书名、书名开头一长串(≥6字前缀)、《书名》式文本 → 置空;混入"分类/作者/最新/章节/字数/点击/更新/状态/简介/目录"标记词或长度 >20 → 置空 |
| `clean_kind` | 分类 | 去"分类[:：>》]"前缀;与书名同文、混标记词(同上+下载/连载)或长度 >12 → 置空(正常分类就是"玄幻/科幻未来"这类短词) |
| `clean_last_chapter` | 最新章节 | 开头误抽书名的剥掉书名;剥完仍含"作者"或长度 >60 → 置空;正常"第N章 …"章节名保留 |

判定取向:**宁可空着也不显示错列垃圾**。

**"只看相关结果"**(app.py,GUI 复选框,默认开):`hit` 事件上屏前本地校验——书名/作者/分类/简介**至少一处**包含关键词或其模糊变体(`_rel_terms`,复用 `make_key_variants`),否则丢弃不上屏。关闭复选框可看全量。与排序共用同一套相关度判定词。
- 顺带修复:书名/目录名叶子文本由 `" ".join` 改为无分隔拼接,避免站点对命中词加 `<mark>/<font>` 高亮而解析出"斗破苍 穹"式空格(实测已恢复为"斗破苍穹")。

#### 5.2.3 跨源同书合并(2026-09-09 新增,`normalize.merge_hits`)

**背景**:清洗只解决"单行脏",同书多源各占一行、字段口径互不相通才是"结果表混乱"的主因。合并范式参照 Legado 官方 `SearchModel.kt`(书名+作者分组)。

- **同书判定键**:`norm_key(name, author)` = (归一化书名, 归一化作者)。书名归一化:去括号内容(卷标/精校标记)→ 去标点/空白 → lower。作者归一化:去标点/空白 → lower。
- **作者通配规则**:一方作者缺失视为与任何作者相容(并入该组);双方非空且不同 → 判为不同书拆组。同名不同作者的组各自独立。
- **组内主字段回填**:组内首个非空 `kind`/`last_chapter` 回填给缺失的行(仅展示语义,下载仍按行自己的源取数据),消除"同一本书部分行有分类、部分没有"。
- **行注记**:`_group_key`(组标识)、`_src_count`(组内源数)、`_group_first`(组首行)。
- **GUI 展示**(保持每源一行,按组聚合视觉):结果表同书相邻(组间按组内最高相关度排序,相关度并列保持先到顺序);组内按**字段完整度**(作者+2 > 分类/最新章节+1)+相关度排前,完整度高的源默认被下载概率更高;相邻组交替底色(`grp1/grp2` tag),组首行书名加"**【N源】**"前缀。排序入口 `app.py _ordered_hits`。

#### 5.2.4 详情页元数据补全(P1,2026-09-09 新增,`engine.fetch_book_info`)

搜索列表的字段清洗只能"救"错列文本;详情页按语义标签抽取的值更干净。下载每本书前(`app.py _try_one`):

1. 先按 `ruleBookInfo` 抓书籍详情页(单请求超时 6s;规则含 JS 或任一异常 → 返回 `{}` 不阻断)。
2. 抽取 `name/author/kind/lastChapter/intro`,过同一套清洗器后**覆盖**搜索列表脏值(仅非空项覆盖),日志记"元数据已按详情页修正"。
3. 失败回退搜索值,继续目录探测/正文下载,行为与 v1.2 完全一致。
4. 只影响导出文件的书名/作者/分类元数据,行选中记忆键(源+URL)不变。

#### 5.2.5 三域搜索(2026-09-09 新增,`app.py var_domain`)

**物理限制**:数千书源的 `searchUrl` 模板只有书名 `{{key}}`,网络按作者/分类搜索不可行。三域搜索采用**网络按书名发起 + 本地按域过滤**的分层设计。

- **UI**:搜索标签「书名:」→「搜索:」;输入框旁增加只读 Combobox 域选择,选项:自动/书名/作者/分类,默认「自动」,持久化至 `sel_state.json` 的 `domain` 字段。
- **网络层不变**:`engine.search_sources` 始终按书名 `{key}` 发起(含模糊变体),不动 engine.py。
- **本地过滤**(`app.py _relevant`):「只看相关结果」复选框(默认开)的行为受域下拉控制:
  - **自动**(默认):书名/作者/分类/简介四域任一命中关键词或其变体即保留(原有行为不变)。
  - **书名**:仅保留书名域命中关键词或变体的行。
  - **作者**:仅保留作者域命中关键词或变体的行。
  - **分类**:仅保留分类域命中关键词或变体的行。
- 显式选「作者」或「分类」时,日志提示「网络仍按书名发起,该域为返回结果内的本地过滤」。
- 排序仍用 `_score_hit` 多字段加权打分(§5.2.1),不因域选择改变权重。

### 5.3 目录(fetch_toc,engine.py:161)
1. 目录入口:默认即 `book_url`;若 `ruleToc.tocUrl`/`ruleBookInfo.tocUrl` 存在,先抓书籍页按规则提取目录页链接。
2. 解析 `chapterList` 节点;每节点取 `chapterName`(缺省 `text`)、`chapterUrl`(缺省 `href`),相对 URL 以**当前目录页最终 URL** 解析,`seen` 集合按 URL 去重保序。
3. 目录分页:`nextTocUrl` 存在则跳下一页继续,最多 8 页;URL 回环(`==cur` 或回到首页)即停。
- 前置校验:`ruleContent` 含 JS → 直接抛错("该源正文规则依赖 JS")。

### 5.4 正文(_fetch_chapter,engine.py:222)
1. 请求章节 URL → `extract_value(dom, content)` 取正文规则结果。
2. 若结果含 HTML 标签(`<` 与 `>`)→ `fragment_to_text()` 转纯文本(块级标签断行、跳过 script/style、空行压缩);否则按纯文本直接使用。
3. 分页:有 `nextContentUrl` 时循环抓下一页拼接,单章 ≤20 页,URL 回环即止。
4. 收尾:应用 `replaceRegex`(支持单条 `##a##b##c##d` 链;`list` 或多行字符串则逐条执行)。
- 章节级失败不致命:写 `error` 字段,导出时以"「[抓取失败原因]」"占位,最终计入 `ok/total`。

### 5.5 并发与失败策略
- 全部用 `ThreadPoolExecutor`;每线程持有独立 `requests.Session`(fetcher 以 `(源名, 线程id)` 做会话 key),**Cookie 不会跨源串扰**,天然支持后续接登录态。
- 超时按源 `respondTime` 换算后夹取 **[4, 12]s**(与 §4、§5.1 一致,`engine._clamp_timeout` 实现为 `min(max(rt/1000, 4), 12)`);正文单章失败静默记录;整书取消抛出 `RuntimeError("已取消")`。
- 并发度分两层:**库默认** `search_sources(workers=24)` / `load_book(workers=8)`;**GUI 实际传值**由 `app.py` 顶部常量决定:搜索 `SEARCH_WORKERS`、校验 `VERIFY_WORKERS`、正文 `DOWNLOAD_WORKERS`。二次开发直接调库时用库默认值,讨论 GUI 表现时以常量值为准。
- **搜索并发实测调优(2026-09-11,v1.5.4)**:全量 3393 源、12 逻辑核、关键词「剑来」——并发 40 → 90.2s;256 → 28.2/28.3s;384 → 18.3/20.4s;512 → 18.7/42.1s(开始不稳)。CPU 全程仅占 1~1.4/12 核,**不是算力瓶颈**;总耗时由"最慢单源最多等 12s"的超时下界主导。推论:**小批量搜索提并发无收益**——实测 240 个源在并发 40~600 之间耗时都是约 12s。故取 **384** 作收益/稳定性拐点。
- **正文下载并发必须保持低值(10)**:同一本书的章节全部来自同一个站,并发越高越容易触发限流/封禁;而搜索/校验是"每源一请求",3393 个源摊在 2107 个域名上,对单站压力不随总并发上升,这才敢开大。

### 5.6 书源校验与有效书源表(2026-09-07/08/09,good 表方案 + 多文件化;判定 2026-09-12 v1.5.5 重订)

判定(2026-09-12 重订):并发 GET 每个书源的 `bookSourceUrl`,**HTTP status < 400 记有效**(202/301/403 等都算活),失败**重试 1 次**再定生死,超时 12s(与搜索对齐),UA 与搜索/下载同一 `fetcher.DEFAULT_UA`。旧口径(200 独裁、超时 5s、Chrome/114 老 UA)曾把约六成活源误判失效 —— 老 UA 被站点 WAF 拦(实测 m.aitbooks.com:老 UA 401 / 新 UA 200)、慢站在 5s 内超时(实测 m.suixkan.com 半秒即 200 却被判死)、202/403 被一票否决。GUI 按钮"✔ 校验书源":`VERIFY_WORKERS` 并发。**多文件按序校验**(2026-09-09):对全部勾选且存在的原始表按序逐个校验,每文件内部 `VERIFY_WORKERS` 并发;进度文案 `文件 i/N · 源 done/total · 有效 x · 失效 y`;停止 = 当前文件中止 + 后续不再开始(已完成文件的 good 表保留)。**搜索兜底救援**(2026-09-12 v1.5.6):第一遍探测完,对失效原因 ∈ {timeout, http_403, http_429, http_503} 的源(`SEARCH_FALLBACK_REASONS`)调 `engine.search_sources(候选, "我的")` 真实搜索一次,搜到书即改判有效——"首页 GET 不通 ≠ 源不可用";日志报"搜索兜底: 对 N 个 403/超时类源复测…"与"救回 M 个";实测本源包 285 个候选救回 0(403 类是整站 WAF,搜索接口同被拦),机制保留给其他源包。

**两张表分工**(逐文件独立):

- **原始全量表**(如 `shuyuan/bookSource.json`)= **校验专用**:每次点按钮都重扫全部勾选文件,永不拿 good 表当校验对象。
- **有效书源表**(`<原名>.good.json`,与 `verify_sources.py` 命令行输出一致)= **搜索/下载专用**:校验**完整跑完**后,在原文件同目录**原子生成**(先写 `.tmp` 再 `os.replace`,中途崩溃不丢旧表),纯 legado 数组可直接导入阅读 App。
- **失效记录**(`<原名>.error.json`,2026-09-12 v1.5.5 新增)= **机器可读分析产物**:每次校验(含全失效文件)都原子生成,供 agent/脚本读取。结构:`{"_meta": {generated_at, source_file, total, ok, failed, untested, rescued_by_search, reason_summary}, "failures": [{source_name, url, reason, status}, …]}`;`reason` 分类:`ok` / `timeout` / `connect`(连不上、DNS 死)/ `http_<状态码>`(如 http_403、http_521)/ `invalid_url`。结束日志打印一行中文分布摘要(如"连不上 788 · http_502 569 · …")。后缀在 `VERIFY_ARTIFACT_SUFFIXES` 内,「清除缓存」/移出清单/重校验前清理都会带走;`is_verify_artifact` 拦截其混入书源清单。命令行 `verify_sources.py` 的 error 结构与此不同(外部库产物),其判定也更苛刻,以 GUI 为准。

**good 表逐文件信任规则**(核心判断,防过期数据冒充有效列表):`sel_state.json` 的 `verify_dones` 字典按文件名记录校验状态(`{文件名: {origin, time}}`);仅当某文件的 `verify_dones[文件名].origin` 匹配该文件当前路径且对应 `.good.json` 存在,加载时才自动用作搜索源;**外部/旧表不自动采用**,搜索暂扫全量并提示"旧表未采用"。缺失/读取失败的文件保留勾选,跳过并日志提示。

**不写 good 表的三种情况**:① 中途点"停止"(有未检测源)→ 该文件作废,已完成文件的 good 表保留;② 该文件全部失效(疑似断网)→ 不写 good 表防空表拉黑(error.json 仍会写入本次失效记录供分析,2026-09-12 v1.5.5 起);③ 写入异常 → 沿用旧表并报错。均不更新 `verify_dones` 记录。

#### 5.6.1 深度校验(2026-09-13 v1.8.0 新增,试搜 + 分类探测)

**动机**:"站点活"≠"能搜到书"—— 大量站首页活着但搜索接口死了或规则失效,用户搜不到任何东西才发现。深度校验在活性探测之后,对**每个活性通过的源**追加两步真实业务探测,给源定质量等级。

**流程**:GUI「🔬 深度校验」按钮 = 先按 §5.6 现有逻辑跑活性校验(`_do_verify` 原样复用,good/error 表语义不变,搜索兜底救援照常),之后对每个活源(n_ok>0 的文件):

1. **试搜**:固定关键词 `DEEP_KEYWORD="我的"`(与搜索兜底救援一致)对该源真实跑一次搜索(`engine.search_one` 单源路径 = §5.2 的展开请求→解析 bookList→四字段清洗,并发 `VERIFY_WORKERS`,每源 1 请求)。判定:`ok`(≥1 本,记命中数与耗时 ms)/ `no_result`(HTTP 成功但书列表空 = 搜索接口死/规则失效/关键词无收录)/ `error`(网络/HTTP 失败,reason 口径同 `_check_one`:timeout/connect/http_XXX)/ `no_search`(无 searchUrl 或 ruleSearch 不合规或规则依赖 JS 且无引擎 —— 无法试搜,**不判死**)。
2. **分类探测**(Legado 的"发现/分类" `exploreUrl` + `ruleExplore`):源带 exploreUrl 且 ruleExplore 有 bookList 才测(`engine.explore_first_page`,每源 1 请求)。exploreUrl 多行/`分类::URL`/JSON 数组多入口**只测第一个入口**;`{{page}}` 缺省按 searchUrl 同款 page=1 展开。判定:`ok`(解析出 ≥1 项)/ `no_result` / `error(reason)` / `none`(无分类能力)。**分类结果只作附加字段,不影响等级**(分类死≠源不可用)。每源至多 2 个额外请求。

**质量等级**:`完整可用`(试搜 ok 且分类 ok)> `可搜`(试搜 ok,分类 none/失败)> `搜索空转`(活但 no_result)> `试搜失败`(error)> `无法试搜`(no_search,活性仍算通过)。

**产物 `<原名>.deep.json`**(原子写,与 error.json 同风格;后缀在 `VERIFY_ARTIFACT_SUFFIXES`,清除缓存/移出清单/混入拦截自动覆盖):

```json
{"_meta": {"generated_at", "source_file", "keyword": "我的", "interrupted": false,
           "alive": N, "search_ok": N, "search_no_result": N, "search_error": N,
           "no_search": N, "explore_ok": N, "explore_no_result": N, "explore_error": N},
 "results": [{"name", "url", "level": "完整可用|可搜|搜索空转|试搜失败|无法试搜",
              "search": {"verdict", "hits", "ms", "reason"},
              "explore": {"verdict", "items", "ms", "reason"}}, ...]}
```

**与 good 表的关键差异**:全部失效文件(n_ok==0)不进深度阶段、不写 deep.json;中途停止时**已测源的结果照常落盘**(`_meta.interrupted=true`,分类阶段未测到的行 explore.verdict=`untested`)—— 深度结果是分析产物,部分数据也有价值。

**搜索联动「只搜试搜通过源」**(辅助行 Checkbutton,默认关,记忆键 `deep_only`):开启后 `start_search` 预筛跳过 deep.json 判定为 `no_result`/`error` 的源,日志报「深度过滤:跳过 N 个试搜未通过源」;**未做深度校验的源(无记录)不跳过**。实现:深度判定灌入引擎模块级表(`engine.set_deep`,键=(书源名, bookSourceUrl) 与 §5.7 跨文件去重身份同口径),GUI 启动/重载时 `_load_deep_tables` 扫描清单各文件 .deep.json 预灌,深度校验完成后即灌;过滤在搜索预筛处 `engine.deep_search_ok(s) is False` 一次判断。

## 6. 规则 DSL 引擎(legado/rules.py)——实现细则

这是与真实 Legado 对齐的核心模块。**设计取向:纯 Python 实现常用子集,遇 JS 显式放弃**。

### 6.1 支持的语法(兼容矩阵)

| 能力 | 语法 | 说明 |
|---|---|---|
| 变量 | `{{key}}` `{{page}}` | searchUrl 中展开;`{{searchKey}}` 等同 key |
| 请求配置 | `url` 或 `url,{"method":"POST","body":"..","headers":{..}}` | `data:`/`javascript:` 前缀拒绝 |
| 元素选择 | `class.x` / `id.x` / `tag.x` / `#x` / `.x` | 简写对照 |
| 按文本找 | `text.章节目录` | 优先精确匹配,退化为包含 |
| 链式 | `A@B`,如 `class.list@a`、`id.content@html`、`text.xx@href` | 逐段在各自后代中取 |
| 下标 | `tag.a.1`(第2)、`tag.a.-1`(末位)、`.all`/`.last` | 负数为倒序索引 |
| 叶子 | `@text` `@textNodes` `@ownText` `@html`(innerHTML) `@all` | 其余按属性名(如 `@href/@src/@value/@data-*`) |
| XPath 子集 | `//meta[@property="x"]/@content`、`//div[@class="y"]//a`、`[2]` 位置、`@attr`、`text()` | 支持 `=`/`!=`/`~=` 谓词;引号内不被 `/` 误切 |
| JSONPath 子集 | `$.a.b`、`$..name`、`[0]`、`[*]`、`['k']`、`[?(@.k=="v")]`、`[?(@.k)]` | dict/list 根可用 |
| dict 变量 | 字段规则为 `{{$.title}}` 或 `前缀{{$.id}}` | root 为 JSON 项时按 JSONPath 回填 |
| 正则链 | 规则尾 `##regex##repl##regex2##repl2` | 在提取结果上逐对 `re.sub`;奇数段自动视为删除 |
| 备选 | `A\|\|B` | 依次尝试直到非空 |
| 拼接 | `A&&B` | 字符串级拼接(宽松近似) |
| 正文 | `fragment_to_text(innerHTML)` | 块级断行/去 script/压缩空行 |

### 6.2 关键解析流程
- 单值 `extract_value(root, rule)`:root 为 dict/list 时优先 `{{$.x}}` 回填或纯 JSONPath;否则按 `||` 拆备选 → 每条按 `&&` 拆段 → 逐段 `extract_chain` → 拼接。返回第一个非空备选。
- `extract_chain` 步骤:取括号外第一个 `##` 之前为规则体(其余为替换尾)→ 按前缀分派:JSONPath(`$`) / XPath(`/`) / 叶子自取(`text`) / 字面量(不可识别文本) / 元素链。
- 元素链:整体先按 `@` 顶层切 token,末段若命中"叶子词表"则摘出为 leaf;每段 `_parse_token` 归一成 `{kind,name,idx}`,`_run_chain` 在 bs4 树中逐段 `find_all` 过滤(类按 class 令牌成员、id 全等、text 用 `_find_text_node`),带下标则收窄,最后统一取 `@text/@html/...` 或节点文本,再跑替换链。
- XPath 采用"**路径转链**":按 `/`(括号外)切段,把 `//tag[@attr='v'][n]` 映射为 `xptag` 步骤 + 谓词列表,尾部 `/@attr` 或 `/text()` 映射为叶子——因此与元素链共用同一执行器。

### 6.3 编码与 DOM
- HTTP 字节解码:`UnicodeDammit(raw, ["utf-8","gb18030","gbk","big5"])` 自动识别(大量笔趣阁老站为 GBK/GB18030)。
- 解析器:默认 `lxml`,异常自动回退 `html.parser`(见 `set_parser`)。
- 相对链接统一 `urllib.parse.urljoin(当前页最终URL, href)`,兼容重定向后的真实基址。

### 6.4 JS 源检测与跳过
- `rules.uses_js_text`:`<js>` 或 `@js` / `@js:` 出现即判依赖 JS(判据不变)。
- `engine.critical_js(src)` 扫描六类关键文本:`searchUrl/header/ruleSearch/ruleToc/ruleContent/ruleBookInfo`,任一命中即返回命中的字段名。
- **v1.7.0 起**:`jsengine.HAS_JS` 为 True(装了 mini-racer)时 `critical_js` 直接返回空 —— 含 JS 的源**不再整源跳过**,脚本由 §6.6 的 JS 引擎执行,失败归约为空结果;无引擎时行为不变(搜索预筛与目录/详情前置校验据此整源跳过)。

### 6.5 与真实 Legado 的已知差异(诚实声明)
1. **JS 为"尽力执行"子集**:JS 引擎可用时跑 `<js>`/`@js:` 与 `{{expr}}`(`java.*` shim 见 §6.6);未实现的 API(`java.cache/cookie/strQuery` 等)、`JavaImporter`(javax.crypto 加密库)、`java.startBrowser` 类脚本运行时归 0 结果(不崩)。无引擎时维持硬边界:含 JS 源整源跳过。
2. XPath/JSONPath 仅为**常用子集**;复杂谓词、函数(如 `contains()`、`count()`)未实现。
3. CSS 组合器:简单后代选择器(空格分隔,如 `.catalog_ls li a`)v1.7.0 起支持(自动拆成 @ 链);其余组合器(`div>a`、`[attr~=v]` 等)未实现,需写作 `@` 链;少数字段写法特殊可能解析不到 → 该源 0 结果,不影响其它源。
4. 登录(loginUi/loginUrl/Cookie)、验证码、代理、`ruleExplore` 发现流均未实现;Legado 的 `@get:{}`/`@put:{}` 命名变量与 `{$.x}` 单花括号变量未实现。

### 6.6 JS 引擎(legado/jsengine.py,v1.7.0 新增)

**定位**:可选依赖(`pip install mini-racer`,0.14 发行包顶层模块名 `py_mini_racer`,内置 V8/ES2020+),`HAS_JS` 探测(含 `timeout_sec` 能力与 V8 起得来双重校验)失败即 False,上层自动回退旧行为,绝不崩。

**线程模型**:MiniRacer 实例不能跨线程并发 eval。每线程一个 isolate 在 384 并发下内存开销过大,故用 **isolate 隔离池**:`BoundedSemaphore(POOL_SIZE=32,环境变量 BOOKDL_JS_POOL 可调)` 限流 + `LifoQueue` 复用;每个 isolate 服务 300 条脚本后回收重建,eval 超时后立即作废重建(V8 终止执行会留残留状态)。单次 eval 超时 5s、单脚本总预算 20s(挂起-重跑 ≤64 轮)。

**Python↔JS 桥 —— 挂起-重跑协议**:mini-racer 0.12+ 的 `wrap_py_function` 只提供 **Promise 异步回调**(`wrap_py_function` 返回 AsyncGenerator),而 Legado 源脚本是**同步**调 `java.ajax(url)` 拿文本,不可行。故:JS 侧 `java.*` 先查本次脚本的备忘录 `__memo`,命中直接返回;未命中把 `(方法名, JSON 参数)` 写入全局 `__pend` 并抛哨兵字符串;Python 捕获 `JSEvalException` 后执行宿主操作,结果写回 `__memo` 再重跑脚本。重跑在函数作用域内 `eval(__script)` —— 变量(含 const/let)每次落全新作用域互不串扰,顶层补全值(Rhino 语义:脚本是表达式即其值)与 Legado 一致;非表达式结尾回退取 `result` 变量。典型脚本 1~3 个 `java.*` 调用,重跑 2~4 次,每次毫秒级。同一 (方法,参数) 只执行一次(备忘录)。

**java.* shim 清单**(网络类走 `fetcher.fetch`,复用 TLS 指纹会话 + Cookie 库,支持 `url,{json}` 请求配置与 option 覆盖):

| 方法 | 说明 |
|---|---|
| `ajax(url[, optionStr])` / `connect(...)` | GET/按 `,{json}` 配置请求,返回响应文本(charset/UnicodeDammit 解码);相对 URL 按当前页 baseUrl 解析 |
| `get(url[, headersStr])` / `post(url, body[, headersStr])` | 显式 GET/POST |
| `ajaxAll(urlList)` | 逐个请求,返回数组 |
| `base64Encode/Decode(str)` | UTF-8;Decode 容忍 URL 安全变体与缺省 padding |
| `md5Encode(str)` / `md5Encode16(str)` | 32 位小写 hex / 中间 16 位 |
| `urlEncode/urlDecode`、`utf8Decode`、`gbkDecode/gbkEncode` | 标准库实现 |
| `timeFormat([ts])` | 秒/毫秒时间戳 → `%Y-%m-%d %H:%M:%S`,缺省当前时间 |
| `getString(rule[, isUrl])` | 在最近抓取的页面(线程局部 page_text)上再跑一条规则 |
| `getVerification / startBrowser` | **明确不实现**(验证码/浏览器),调用即整条归空 |

未实现的 API 名调用后由 Python 判"未实现"→ 整条 JS 归空(该源 0 结果,不崩);`CryptoJS`/`Base64` 类源内自带纯 JS 实现,V8 原生能跑,无需 shim。

**rules.py 接线**(全部仅在 `HAS_JS` 时生效,否则与旧版逐字节一致):
- `<js>…</js>` 内嵌:前段规则先跑得 `result`(支持 `||` 备选,如 `$.data.chapter_link||$.data.current.link`),JS 返回值作为该段结果(**不自动抓取**,`java.ajax(result)` 已在 JS 内抓完);其后规则段(如 `$..body`)把 JS 结果(JSON 优先解析,否则按 HTML DOM)作新根继续提取。
- `@js:` 前缀:前段规则结果作 `result`(如 `$.value@js:java.base64Decode(result)`),eval 返回值即结果;集合规则(bookList)JS 返回 JSON 数组可直接作节点列表。
- `{{key}}/{{page}}/{{searchKey}}` 文本替换**原样保留**(先替换后跑 JS);其余 `{{expr}}` 按 JS 表达式求值(注入 result/key/page),`{{$.x}}` dict 变量行为不变。
- searchUrl/请求 URL:文本替换后若含 `<js>`/`@js:` 则注入 key/page/searchKey/baseUrl 跑 JS,产出文本按现有 `url,{json}` 口径解析(典型:`"https://…?keyword={{key}},"+JSON.stringify(option)`);失败保留原文容错。
- header:`@js:`/`<js>` 生成 JSON → 解析为 dict,失败回退默认 UA(与旧文档行为一致)。
- 页面上下文(baseUrl/page_text/key/src_key)存线程局部,engine 在搜索/详情/目录/正文的每次抓取后刷新 —— 384 并发互不串扰。

**性能与开销**:import 时探测一次(V8 起停 ~50ms);空池冷启动每 isolate ~10ms;搜索路径上仅含 JS 的源多付"JS 求值"(毫秒级)+ 可能的额外 `java.ajax` 请求;池 32 并发下 isolate 不是吞吐瓶颈(CPU 占用远低于网络等待)。

## 7. HTTP 层(fetcher.py)——浏览器 TLS 指纹 + Cookie 自动维持(v1.6.3 重写)

参照 Legado HttpHelper 三层容错(2026-09-13 v1.6.3,详见修订记录):

- **TLS 指纹**:`curl_cffi`(impersonate=chrome124)替换 requests 执行请求,带真实 Chrome TLS 指纹 —— 指纹检测型 WAF 的 403/502 主对策;未安装时自动回退 requests。**系统代理必须显式传入**:requests 会读 Windows 注册表代理,而 curl_cffi 只认环境变量,Clash 类用户不传代理会全部直连、被墙站一律连接重置(`_system_proxies()` 经 `urllib.request.getproxies()` 拿注册表代理)。
- **超时口径**:curl 的 timeout 是总时长语义(requests 是连接/读各算),对 curl 会话放宽一倍 —— 同 Legado `callTimeout=max(15,read)*2` 口径。
- **兼容回退**:指纹会话连接失败时用原 requests 会话再试一次(等价 Legado COMPATIBLE_TLS —— 老协议/老 TLS 站点对 chrome124 指纹会握手失败),单次无重试。
- **Cookie 自动维持**(legado/cookie_store.py):响应 Set-Cookie 自动按域存入 sqlite(`shuyuan/cookies.db`)+ 内存镜像;请求前按"会话 jar < 运行时库 < 显式 Cookie(用户登录头按名优先)"合成 Cookie 头;跨线程/跨次运行维持,登录一次不过期。落盘由 10s 定时线程批量刷 + atexit 兜底(384 并发下不做每响应磁盘写)。属用户会话凭据,「清除缓存」不清理。
- **URL option 重试/编码**:`rules.parse_request` 新增解析 `{"retry":N}`(非 2xx 与连接异常重试 N 次,退避 0.5s×次数;默认 0 不重试,与 Legado 一致)与 `{"charset":"gbk"}`(显式解码优先于自动识别);engine 五处调用点(搜索/详情/目录解析/目录翻页/正文)全部透传。
- **模块级入口**:`fetcher.request()`(指纹会话 + cookie 库)供校验 `_check_one` 使用;`fetcher.TIMEOUT_EXCS` 统一 requests/curl_cffi 两种超时异常的归类。

## 8. 导出(export.py)

### TXT(`export_txt`)
- 文件名:书名的非法字符(`\ / : * ? " < > |` 与换行)替换为 `_`,截断 80 字符。
- 编码:**UTF-8 with BOM**(`utf-8-sig`),保证记事本/旧阅读器中文不乱码。
- 结构:书头(书名/作者/来源/章数统计)→ 分隔线 → 逐章 `章节名\n\n正文`;抓取失败的章节以 `[抓取失败<原因>]` 占位。

### EPUB3(`export_epub`)
- 手工以 `zipfile` 生成,非第三方库:
  - `mimetype`(**第一个条目且 ZIP_STORED**,值 `application/epub+zip`)
  - `META-INF/container.xml`、`OEBPS/content.opf`(OPF3:identifier/title/language/creator + manifest + spine,`nav.xhtml` 带 `properties="nav"`)、`OEBPS/nav.xhtml`(目录导航)、`OEBPS/style.css`、`OEBPS/chapNNNN.xhtml`。
- 章节正文:按空行切 `<p>`,HTML 全量转义;空章节写入 `[抓取失败]`。
- 校验方式(原 e2e2.py,脚本见开发副本):zip 名称首项、mimetype 字节、container/opf/nav/全部 xhtml 逐一 `xml.dom.minidom` 解析通过。

## 11. 已知限制与故障排查

### 限制
1. 书源生存率低:合集 3393 源大量域名在售/被墙。实测近"0905 校验"分组 549 源,约 1/4 存活(47s 探出 151 命中)。

### 排查速查表
| 现象 | 原因 | 处置 |
|---|---|---|
| 搜索"完成"但 0 条 | 分组内源全失效/全 JS;或精确模式确实无收录;或"只看相关结果"过滤后全被剔 | 换分组(优先选校验过或带日期的分组),或换关键词;打开「模糊搜索」让其自动变体重试;确认「只看相关结果」勾选状态 |
| 结果混入无关书(书名作者都不含关键词) | 站点无视搜索词返回热门书充数 | 开「只看相关结果」(默认开)即本地剔除 |
| 作者/分类列为空 | 源字段规则抽错列,清洗器判定垃圾置空(§5.2.2) | 属预期(宁空勿乱);信息仍在该源详情页 |
| 校验状态标签显示"旧表未采用" | good 表非本程序校验生成(如命令行 verify_sources.py 产出) | 点"✔ 校验书源"完整跑完即生成新表并自动采用 |
| 特定源搜不到、别的源正常 | 该源死亡或规则不兼容 | 属正常;改选其它命中 |
| 下载中大量 `[抓取失败]` | 站点限流/章节页反爬/规则缺页 | 稍后重试;换源;提高(engine)重试或代理 |
| 下载报"目录为空" | 需登录/被封/目录走 JS | 换书源 |
| 打开报 tkinter/ModuleNotFound | 用了无 tkinter 的解释器,或依赖未装 | 用系统 Python 3.14.7 启动;`pip install requests beautifulsoup4 lxml websocket-client curl_cffi` |

                        # 清洗(§5.2.2),错列垃圾文本为空串
search_sources 签名   = search_sources(sources, key, on_progress=None,
                        stop=None, workers=24, on_hit=None, fuzzy=False)
                        -> [Hit,...]  # on_progress(done,total,msg)、on_hit(hit)
                        # 注:workers 为库默认;GUI 传入 40,见 §5.5
load_book 签名        = load_book(hit, on_progress=None, stop=None, workers=8)
                        # 注:GUI 传入 10,见 §5.5

search_one(source, key, timeout=None) -> (hits, err_reason)
                        # 深度试搜单源(v1.8.0):err=""=网络存活(可 0 命中=空转);
                        # "no_search"=无法试搜;其余=timeout/connect/http_XXX
explore_first_page(source, timeout=None) -> (items, err_reason)
                        # 深度分类探测(v1.8.0):exploreUrl 第一入口→bookList 计数;
                        # "none"=无分类能力;其余口径同上
set_deep(table) / deep_search_ok(s)
                        # 深度判定表(键=(书源名,bookSourceUrl)):搜索过滤联动,
                        # deep_search_ok → True=通过 / False=空转或失败 / None=无记录
fetch_toc 返回       = [(章节名str, 章节URL), ...]   # 保序、URL去重
load_book 返回       = {title, author, kind, source, book_url,
                        chapters:[{name,text,error}], total, ok}
export_txt/epub(book, out_dir) -> 文件绝对路径str

## 14. 打包与发布

> 本节是**打包发布的唯一权威说明**;`README.md` 的「🔨 打包单文件 EXE」只保留命令速查,细节以本节为准。

### 14.1 打包命令
```bash
pip install pyinstaller
pyinstaller --noconfirm --clean --onefile --windowed --name 小说下载器 app.py
```
参数含义:`--onefile` 单文件、`--windowed` 隐藏控制台(GUI 必需)、`--name` 指定中文 exe 名、`--clean` 清缓存避免旧构建污染。

### 14.2 产物与部署约定
- 产物位于 `dist\小说下载器.exe`,需与 `bookSource.json` **置于同一目录**;app 在打包态会检测 `sys.frozen` 并从 exe 所在目录读取书源包(见 `app.py` 路径解析逻辑),因此书源包可独立替换而无需重新打包。
- 发布走 GitHub Releases(本地 `release\` 归档目录已清理,重打包时按需重建);官网页面源码在 `docs\`,经 GitHub Pages 发布。
- 第三方依赖(`requests` / `beautifulsoup4` / `lxml` / `websocket-client` / `curl_cffi`)由 PyInstaller 自动收集(curl_cffi 若打包后报缺 DLL,加 `--collect-all curl_cffi`);**可选依赖 mini-racer**(JS 引擎,v1.7.0):发行包顶层模块名为 `py_mini_racer` 且带 V8 动态库,自动收集如不生效则加 `--collect-all mini_racer`(实测确认前先打包试运行,GUI 日志出现「JS 引擎:已启用」即收集成功)。一般无需 `--hidden-import`;若新增依赖后运行报 `ModuleNotFoundError`,再补 `--hidden-import=<包名>`。

### 14.3 已知注意事项
- 打包所用解释器**同样必须含 tkinter**,否则构建成功但运行即崩(排查见 §11)。
- 中文 exe 名在部分终端下需 `chcp 65001`;建议以资源管理器双击验证而非命令行启动。
- `--onefile` 首次启动需解压到临时目录,冷启动约慢 1–3 秒,属正常现象。
