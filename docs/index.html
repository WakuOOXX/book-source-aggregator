它解决的是"搜得到、下得全"

这些站你大概不陌生:今天还能开,明天就换了域名。工具默认把这些状况处理掉。

批量书源聚合搜索

读入 Legado 书源包,一次搜索并发打向全部书源。返回结果边搜边进表格,第一个活源几秒内就出现,不用等最后一个跑完。

模糊搜索兜底

名字记不全也能找。直搜无果时生成变体(取首段、去尾字、超长截前四字),只对上一轮网络还活着的源重试,命中即停。

多选 / 框选,一次抓一批

选书和资源管理器一样:单击选一本,Ctrl 逐个增减,Shift 连续选,按住左键拖出蓝框批量选。下载时选「下载单一」或「合并下载」。

失效源自动跳过

下载前先探测候选源,单请求 6 秒、单源 15 秒封顶,半死源快速失败并标红跳过,直到找到能下全的源。正文逐章抓取,支持目录分页拼接。

规则引擎是纯 Python,不依赖浏览器

自研引擎解析书源的 class / XPath / JSONPath 选择器、正则替换与多页正文;依赖 JS 脚本或登录态的源直接跳过,不报错不中断。

一键校验书源 + 三域搜索

点「校验书源」逐个体检清单里的文件,每个文件生成一张有效书源表,之后搜索只扫活源。搜索框可按书名 / 作者 / 分类三域过滤,同一本书的跨源结果聚成一组展示。

多书源文件,一个清单管理

「书源文件」下拉把多个书源 JSON 收进一个清单,合并时按 (书名, 站点 URL) 去重,校验过的优先。清单和选项会记住,重启不丢;行尾 ✕ 移出,随时再从别的文件夹加回来。

缓存可以清,书源清单不动

校验出来的有效表是缓存,占了地方就点「清除缓存」一次清掉,顺带把选项重置回默认值;你选的书源清单不受影响。

首次使用三步

不用装 Python。解压、导入书源、搜索下载。

下载解压

把 zip 解压到任意目录,双击 小说下载器.exe。首次打开是没有书源的,点顶部「打开目录」会创建并打开 shuyuan\ 文件夹。

导入书源

把 Legado 书源 JSON 放进 shuyuan\,再点「书源文件 → + 新加入书源…」加入清单(支持多选,不在该目录的文件会自动复制进去)。*.good.json / *.error.json 是校验产物,不会被当成书源。

搜索下载

输入书名搜索,双击结果下载。点「校验书源」可以先筛出活源,之后搜索更快;缓存占地方了点「清除缓存」清掉即可。

常见问题

搜索完一个结果都没有,是坏了吗?

大概率不是。这类合集书源站寿命短,同一批源里经常大半已经失效。换个分组(优先选校验过或带日期的)、换个关键词再试;开着模糊搜索会让工具自动换词重试。

为什么有些书源搜不到?

两类原因:站本身挂了,或它的规则依赖 JS 脚本 / 登录态。后者工具会直接跳过,不报错。命中率高的做法是挑大站结果,或在多个分组重复搜。

导出的 EPUB 能在哪些设备上看?

标准 EPUB3,Kindle 之外的阅读器基本都认:手机(微信读书导入、Apple 图书、静读天下等)、电纸书、电脑浏览器都能打开。Kindle 需要先转 MOBI/AZW3。

书源会更新吗?要不要重装程序?

不用。书源就是你放进 shuyuan\ 的那些 JSON 文件,拿到新版覆盖同名文件即可,exe 不用动。

为什么不内置书源?

一是合规:书源来自社区共享,内容不可控,内置了有法律风险。二是实用:书源站换得快,不内置的话拿到新文件覆盖进去就行,不用重下整个程序。

这是爬虫吗?有没有风险?

它只是把你手输的书名发给书源站自己的搜索页,再按公开规则读回正文。请只下载你有权阅读的内容,勿用于侵权用途,详见下方声明。
